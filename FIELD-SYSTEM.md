## The Golden Thread

> **EXPERIENCE → DOCTRINE → JUDGMENT → TOOL → FRICTION → EVIDENCE → UPDATE**

The Golden Thread is the traceability rule. An idea should be inspectable from where it came from, through what it became, into how it is used, stressed, observed, and revised.

**Trace Everything. Duplicate Nothing.**

## Evidence Ladder

Readiness claims strengthen only when evidence strengthens.

    LOOP EVIDENCE
          ↓
    SUPERVISOR CALIBRATION
          ↓
    NEAR-MISS COMPARISON
          ↓
    FIELD OUTCOME CORRELATION
          ↓
    VALIDATED READINESS CLAIM

Evidence status must not be inflated. Use explicit boundaries such as:

**ILLUSTRATIVE · SIMULATED · PUBLICLY REPORTED · FIELD-OBSERVED · VALIDATED**

A public incident does not validate a proposed instrument. A simulation does not establish field effectiveness. A model baseline is not a human-participant result. Unknown operational thresholds remain:

**UNKNOWN / REQUIRES AUTHORITATIVE VERIFICATION**

The [Operational Readiness Lab Evidence Dashboard](https://github.com/theedreif/operational-readiness-lab/blob/main/evidence/dashboard.md) is the portfolio map to the evidence; it is not itself the evidence.

## Rule for Adding Anything New

> **A new idea does not earn a repository because it is interesting. It earns one only if the Field System cannot adequately BUILD, DECIDE, POSITION, COMMUNICATE, PROVE, UPDATE, or DEPLOY it through an existing Door.**

Before adding a repository, framework, instrument, or named layer:

1. **Place it first.** Which existing Door owns the function?
2. **Trace it.** Where does it sit on the Golden Thread?
3. **Check duplication.** Does a canonical artifact already perform the job?
4. **State the evidence.** What is known, simulated, observed, or validated?
5. **Name the gap.** What necessary function cannot be expressed through the existing architecture?
6. **Earn the addition.** Add architecture only when the gap is functional, persistent, and evidenced.

If those conditions are not met, extend an existing Door.

## Governance

The architecture is frozen as **Ed Reif Field System v1.0** until evidence demonstrates that the architecture itself is inadequate.

Changes to this Manifest must be explicit, versioned, and justified by a documented functional or evidentiary need. Do not silently redefine the Seven Doors in downstream repositories.

Repository READMEs may explain their own Door, doctrine, tools, local loops, cases, and evidence. For Field System-wide definitions, they should link here.
